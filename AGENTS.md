# Инструкция для агента: установка адаптера RKDash

Этот файл — для Hermes-агента, которому дали ссылку на этот репозиторий. Человеку ничего
читать не нужно: выполни шаги ниже и отчитайся.

## Что происходит

Агент подключается к платформе ресторанной аналитики **RKDash** и получает её инструменты
(данные ресторанов, доска задач, события). Дальше он может брать задачи с доски, отвечать
на вопросы по данным и оставлять отчёты прямо в карточках.

## Шаги

### 1. Спроси у человека ключ платформы

Ключ выпускается в панели RKDash: **Цифровые сотрудники → карточка исполнителя → «Комплект
для установки»**. Он выглядит как `rk_live_…` и показывается один раз.

Если человек дал другую ссылку на панель (свой домен), уточни и её — по умолчанию
`https://rkdash.com`.

### 2. Установи адаптер

```bash
git clone https://github.com/geniok1980/hermes-rkdash-adapter.git /tmp/rkdash-adapter
RKDASH_KEY=<ключ> sh /tmp/rkdash-adapter/install.sh
```

Если у агента заведён отдельный профиль, передай его явно: `RKDASH_PROFILE=<профиль>`.
Установщик поставит навык, пропишет MCP-сервер `rkdash` в конфиг нужного профиля и проверит связь.

### 3. Включи службу, к которой обращается платформа

Платформа зовёт агента прогоном по задаче из доски. Для этого нужна включённая служба:

```env
API_SERVER_ENABLED=true
API_SERVER_HOST=0.0.0.0
API_SERVER_PORT=9131
API_SERVER_KEY=<секрет>
```

Секрет — не ключ платформы: это ключ службы агента. Сгенерируй его сам (`openssl rand -hex 24`)
и запиши в `.env` профиля. Чтобы платформа могла достучаться, адрес снаружи должен быть доступен
по `https`; если агент и платформа в одной сети — допустим `http` с разрешением в карточке
исполнителя. Блок в `.env` добавляет сам установщик — останется подставить свой секрет.

### 4. Перезапусти Hermes

Навык и инструменты подхватываются при старте. После перезапуска:

```bash
hermes mcp test rkdash        # ожидаемо: Connected и список инструментов
sh /tmp/rkdash-adapter/verify.sh
```

### 5. Отчитайся человеку

Скажи, что сделано, и что осталось на его стороне:

1. В панели RKDash включить MCP-сервер («Настройки → API») — без него инструменты не появятся.
2. Подключить агента: «Цифровые сотрудники → Подключить агента», транспорт **«Внешний агент
   по API server»**, адрес агента и его `API_SERVER_KEY`, кнопка «Проверить».
3. Дальше задачи с доски, назначенные этому исполнителю, приходят агенту прогоном.

## Правила работы с платформой

- **Не выдумывай данные.** Нет инструмента — нет ответа. Ноль вместо «нет данных» — ложь.
- **Изменения (цены, склад, настройки) — только с подтверждения человека.** Сначала покажи,
  что изменится и на сколько, дождись «да».
- **Отчёт по задаче — комментарий в карточке** (`add_card_comment`), а не свободный текст в чат.
- **Персональные данные сотрудников и гостей** за пределы платформы не выгружай.
- Ключ платформы — это права агента: что не разрешено ключом, того не существует.

## Если что-то не сработало

- `hermes mcp test rkdash` не видит сервер — проверь, в тот ли профиль записан конфиг
  (`RKDASH_PROFILE`, `RKDASH_CONFIG`).
- Связь есть, но инструментов нет — в панели выключен MCP-сервер.
- Прогон по задаче не приходит — не включена или недоступна служба агента (шаг 3),
  либо в карточке исполнителя не указан ключ агента.
